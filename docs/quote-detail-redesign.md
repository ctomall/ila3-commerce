# 报价单详情 · 单页重设计验收

选这一页做验收，是因为它同时压着本轮三个结论：格式化（金额/日期）、状态迁移（下一步动作）、权限（谁能看到动作）。原型 `quote-detail-after.png`，现状 `quote-detail-before.png`，都在 `/home/pro/dsh/shots/`。

## 一、现状实测（1280×860，/backend/sales/quotes/485b88ce…）

| 指标 | 实测值 | 问题 |
| --- | --- | --- |
| 明细表首行位置 | **top 623px** | 首屏 72% 被抬头与元信息吃掉，一屏只看到 2 行商品 |
| 双口径金额单元格 | **4 个** | 每格上下两行 `US$148.00 含税 / US$120.00 不含税`，横向无法比较 |
| 主操作区图标按钮 | **17 个**（main 内 <44px 无文字） | 发送/时钟/操作/删除都是图标，用户得逐个猜 |
| 状态呈现 | 灰色胶囊「草稿」 | 状态后面没有「下一步该做什么」 |
| 唯一红色强调 | 「删除」 | 危险动作成了视觉焦点，主流程动作反而隐形 |
| 元信息卡片 | 客户卡 + 4 张字段卡（每张约 60px） | 单行信息占了 4 行高度 |

## 二、设计决策

1. **抬头合成一行**：单号（等宽）、客户、日期、币种、渠道、有效期一条读完，替代「客户卡 + 四张字段卡」。
2. **一个主操作，随状态变化**：草稿 →「发送给客户」；已发送 →「标记客户已确认」；已确认 →「转为订单」。图标动作降级到「更多」。
3. **一行一个金额口径**：单价与合计统一用不含税，税额单列；含税合计放在合计区最后一行。
4. **状态写成一句话**：「草稿 · 尚未发送给客户，发送后客户可在线确认」——状态不只是颜色。
5. **删除退到更多菜单**，主操作区只留预览与下一步。

## 三、验收清单（可执行）

| 断言 | 现状 | 目标 |
| --- | --- | --- |
| 明细表首行 `top` | 623px | **≤ 340px** |
| 双口径金额单元格数 | 4 | **0** |
| 主操作按钮数（有中文文案的主按钮） | 0（全是图标） | **≥ 1，且文案随状态变化** |
| 状态旁是否有下一步说明 | 无 | **有**，一句话 |
| 主操作区是否有危险色按钮 | 有（删除） | **无** |
| 金额列 `tabular-nums` | 有 | 保持 |
