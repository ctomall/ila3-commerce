## 2. 我会加什么（一个变更集，可回滚）

1. `OutboundTransport` 的**真实实现**：调用上面选定的渠道发一条消息，返回 provider 消息 id；
   失败按现有 `transport_failed` 处理，且退还已消费的 `send` 额度（已实现）。
2. **默认关闭的外发开关**：`LEADGEN_OUTBOUND_ENABLED`（未设置 = 只跑模拟传输，行为与今天完全一致）。
   开关打开但没配置渠道时，dispatch 仍拒绝并报 `outbound_transport_unavailable`，不会假装发送。
3. **预留与员工的归属**：现在 lease 绑定草稿；真实外发前把 `scope_kind='employee'` 的桶与调用者绑定
   （需要一次**生产迁移**加一列，按规矩单列审批）。
4. 回执入口（`leadgen_message_receipts` + `POST /leadgen/webhooks/providers/{provider}`，验签 + `provider_event_id` 去重），
   退信/投诉自动进抑制名单（抑制名单的读写已完成）。

## 3. 第一次真实外发会是什么样

- 目标：**一条**消息，发给 §1 的测试地址；
- 前置：草稿 → 审批（绑定正文）→ 预留（绑定草稿）→ 抑制检查 → dispatch；
- 代码里已强制：一个审批只能投递一次、正文改动即失效、抑制命中直接拒、额度原子扣减、权限位校验；
- 失败即回滚：`LEADGEN_OUTBOUND_ENABLED` 关掉 + revert 提交，一次部署生效。

## 4. 我会交什么证据

1. 真实投递的 provider 消息 id 与渠道侧回执（截图/日志）；
2. `leadgen_sends` 行（`state=accepted`、`provider_key=<渠道>`、`provider_message_id`）；
3. 同一审批第二次被拒（409）、改正文被拒（409）、抑制命中被拒（409）——在真实投递开启状态下重跑；
4. 回滚演练：关开关 → 再 dispatch → 仍走模拟传输、外部零投递。
