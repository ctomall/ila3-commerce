## 1. 四层「完成」口径（互相不能替代）

| 声明 | 判据 | 拒收 |
|---|---|---|
| 代码完成 | diff 存在 + `yarn typecheck` 0 + `yarn lint` 0 + `yarn generate` 干净 | 任一未跑 |
| 测试通过 | 具名套件 + 用例数 > 0 + **至少一次负向对照** | 空跑绿（如 `passWithNoTests`）、只用 marker 字符串断言 |
| 已部署 | 线上返回的构建 SHA == 本次 SHA + 健康检查 200 + 新行为线上复现 | 本机 build 成功、只有 127.0.0.1 可访问 |
| 业务验收 | 具名人类签字 + 每条「实测」列有可复跑命令 + 显式「未达成」 | 签字人=构建者、无「偏离与例外」段 |

页脚已渲染 `v0.9.0 (<sha>)`，可直接作为「已部署」的证据锚点。

## 2. 两种压测口径（必须分开报）

| 口径 | 定义 | 目标（建议） | 度量 |
|---|---|---|---|
| 在线人数 | 同时保持会话的试用用户数 | 2 业务员 + 1 主管 = 3 | 会话数与内存/CPU |
| 并行 Run | 同时执行的 DSH 研究任务数 | ≤ 员工数 × 2 = 6 | 队列长度、Run 时长 P95、失败率 |

**不要用一个数糊两个概念**：3 个在线用户可能开出 12 个 Run，也可能是 3 个。

## 3. 试用范围（建议默认，待确认 D10）

| 项 | 建议 |
|---|---|
| 人员 | 2 业务员 + 1 主管 |
| 时长 | 2 周 |
| 额度 | 每人每周 12 条候选；发送 0（首期只做草稿与审批，不真实外发） |
| 停止条件 | 任一安全用例失败 / 发送回执异常 / 投诉 → 立即停并回滚 |
| 观察指标 | 候选通过率、重复率、审核时长、额度耗尽次数、错误率 |

## 4. 备份与恢复（演练，不碰生产）

| 项 | 做法 | 证据 |
|---|---|---|
| 备份 | `pg_dump` 到独立目录，校验大小与行数 | dump 文件 + `select count(*)` 对照 |
| 恢复 | 恢复到**独立库**，跑 `yarn db:migrate` + 冒烟接口 | 恢复库上的 `/api/healthz` 与列表接口 200 |
| 回滚 | 代码回退到上一 tag + 数据库保留（迁移只前进不后退） | tag 列表 + 回退后 SHA |

**不演练生产库**；恢复在独立库上做，属只读+隔离环境。

## 5. 版本固定与灰度

- 版本：部署只用打 tag 的构建；页脚 SHA 必须与 tag 一致（`scripts/check-version-tag.mjs` 已在构建门里）。
- 灰度：先放 1 个员工，观察 1 天，再放第 2 个；出问题回退 tag。
- 回滚触发：错误率 > 5%、发送异常、任一安全拒绝被绕过。

## 6. 压测与观察清单

| 检查 | 方法 | 阈值 |
|---|---|---|
| 登录/列表 P95 | 3 用户并发请求关键页面 | < 1.5s |
| 并行 Run 排队 | 同时提交 6 个 Run | 队列不丢任务，超时可见 |
