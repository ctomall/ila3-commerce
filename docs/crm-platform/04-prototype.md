# M3 原型 · 中文六页（规格）

> 定位：**原型，不是生产**。所有页面顶部常驻横幅「原型演示 · 非生产数据」，路由前缀 `/backend/prototype`，`navHidden`，不进入任何业务菜单。
> 目的：在写 M5/M6 业务之前，先把「中文 · 浅色蓝白 · 表格优先 · 详情抽屉 · AI 随动作出现」这套交互跑通，并让 M4 的安全工作有具体界面可对照。

## 1. 六页与路由

| # | 页面 | 路由 | 主要数据（原型期） | 生产中来源 |
|---|---|---|---|---|
| 1 | 业务员首页 | `/backend/prototype` | 本人本周候选/待审/入库/额度 | `leadgen_*` + `customer_entities`（按 owner） |
| 2 | 开发任务 | `/backend/prototype/tasks` | 任务表 | `leadgen_research_runs` + 配额桶 |
| 3 | 候选审核 | `/backend/prototype/candidates` | 候选表 + 证据 + 验证结论 | `leadgen_candidates` + `_evidence` + `_verifications` |
| 4 | 客户列表 | `/backend/prototype/accounts` | 公司表（归属/阶段/最后触达） | `customer_entities` + `customer_companies` |
| 5 | 客户详情 | `/backend/prototype/accounts/detail` | 资料 + 时间线 + 助手建议（抽屉） | 同上 + `customer_interactions` |
| 6 | 邮件草稿审批 | `/backend/prototype/drafts` | 草稿 + 审批状态 | `leadgen_drafts` + `_approvals` + `_sends` |

连贯性：六页共用一条页签栏与同一横幅，页面之间可直接跳转；从候选审核点「查看客户」进客户详情，从客户详情点「写邮件」进草稿审批。

## 2. 视觉与组件约束

- 浅色底，正文墨黑 `--foreground`，主按钮用现有 `Button` 的 `default` 变体（不新造主色），强调色只用现有 tokens。
- 表格优先：列表页 = 一张表 + 顶部筛选条；详情页 = 头部资料条 + 下方分块。
- 详情用**右侧抽屉**（原型用静态面板占位，标注「抽屉」）。
- 密度：与现有列表一致（行高 ≤ 41px，`tabular-nums` 用于数字列）。
- 复用：`Page`/`PageBody`、`Card`、`Badge`、`Banner`、`Button`、`DataTable`（生产期）、tokens。

## 3. 状态覆盖（每页必须能演示）

| 状态 | 怎么演示（原型期） | 生产期判据 |
|---|---|---|
| 空 | 切换「状态」为 空 | 查询返回 0 行 |
| 无权限 | 切换为 无权限 | 403 + 说明 |
| 错误 | 切换为 错误 | 请求失败，表格进错误态（复用已修的 `error` 分支） |
| 预算耗尽 | 切换为 预算 | 配额硬拦截 429/提示 |
| 重复 | 切换为 重复 | 去重命中 → 「已存在」 |
| 并发冲突 | 切换为 冲突 | 409 + 版本号 |
| 发送未知 | 草稿页切换为 未知 | provider 超时 → 先查后发 |
| 断线取消 | 任务页切换为「已取消」（已实现，见 `proto-tasks-cancelled.png`） | Run cancelled，额度退回 |

实现：每页一个「状态」下拉（仅原型可见），切换后渲染对应占位。**这些不是真实业务状态机**，只是把要覆盖的界面先摆出来。

## 4. 每页结构

### 4.1 业务员首页
四张卡（本周候选 / 待我审核 / 已入库 / 额度余量）+ 「今日任务」表（任务 / 产品市场 / 状态 / 候选数）+ 「最近动态」列表。
AI 入口：卡片右上「让助手继续调研」按钮（原型禁用，hover 说明）。

### 4.2 开发任务
顶部：新建任务（禁用）+ 筛选（状态/产品）。
表：任务名 / 产品·市场 / 来源 / 额度(已用/上限) / 候选 / 状态 / 更新时间。
行内操作：查看候选、取消（取消需二次确认，原型为静态说明）。

### 4.3 候选审核
左：候选表（公司 / 域名 / 联系人 / 证据数 / 验证 / 去重 / 提交时间）。
右：抽屉内容（选中行）——公司信息、证据列表（URL + 抓取时间 + 摘要）、验证结论（通过/需复核/不通过 + 规则版本）、审核动作（通过入库 / 拒绝 / 合并到已有公司）。
文案要求：**「验证通过」不等于「邮箱可送达」**，界面必须把两者分开展示。

### 4.4 客户列表
表：公司 / 归属 / 阶段 / 最后触达 / 可触达（有/无邮箱）/ 更新时间。
顶部：搜索 + 筛选（归属/阶段/可触达）+ 视图。

### 4.5 客户详情
头部：公司名 + 域名 + 归属 + 阶段 + 「写邮件」按钮。
三块：资料（自定义字段）、时间线（互动/候选/邮件）、助手建议（只读，标注「AI 建议 · 需人工确认」）。
抽屉：证据/来源。

### 4.6 邮件草稿审批
左：草稿列表（收件人 / 主题 / 状态 / 更新时间）。
右：正文 + 元信息（收件人 / 模板版本 / 正文 hash）+ 审批按钮（批准 / 驳回 / 撤销批准）+ 发送状态条（草稿→待批→已批→已发→回执）。
高风险提示：正文变化后必须重新审批（界面显式写出）。

## 5. 验收（M3 门禁）

1. 六页截图各一张（1440×900，中文，无英文残留）。
2. 每页至少演示 3 个状态（空/错误/无权限 + 该页特有状态）。
3. 对比度门禁 12/12；`ui-regression` 18/18（原型页不破坏既有断言）。
4. 页面顶部横幅存在且文案含「原型」。
5. 原型路由不出现在任何业务菜单（`navHidden`，用 nav 基线 diff 证明入口数不变）。

## 6. 明确不做

- 不接真实数据、不写库、不发送任何邮件。
- 不新增业务功能入口到主菜单；原型页 `navHidden`。
- 不做移动端适配（与本阶段目标无关）。

## 7. 实现位置

`src/modules/crm_prototype/`（app 模块，`from: '@app'`）。复用 `customers.companies.view` 作为访问门（不新增 ACL 功能点，避免要给角色授权才能看到）。页面全部 `navHidden: true`。

## 8. 浏览器验收（2026-11-08 新增，M3 门禁的自动化部分）

`04-prototype.md` 第 5 节的验收此前只靠截图和人工对照——截图不会因为页面改坏而变红。`.ai/qa` 那时只有 Playwright 配置、**0 条 spec**，`yarn test:integration` 直接 `No tests found` 退出 1：一条没有任何东西能失败的路径。

现在：`.ai/qa/tests/crm-prototype.spec.ts`，**3 条用例 / 15 个断言**，已纳入 `crm-verify-all --full` 第 15 道门。

| 断言 | 为什么值得存在 |
|---|---|
| 六页逐页 200，横幅含「原型演示」「非生产数据」「不落库」「不发送」 | 横幅是这个原型**唯一的**"这不是真实数据"提示，文案消失就等于承诺消失 |
| 每个原型子导航 6 个链接、`aria-current="page"` 恰好 1 个且等于当前页标签 | 六页互相知道谁被选中，避免"看起来在 A 页其实在 B 页" |
| `/backend` 上**没有**该横幅、侧栏**没有**六个原型入口，且**要求真的停在 `/backend`**（不是被重定向到登录页）；匿名可见的 `/`、`/login` 也没有横幅 | 这是有判别力的那条。独立 QA 指出：不校验最终 URL 时，未登录被弹到登录页也会全绿——因为登录页上这些元素count 都是 0。已补 URL 与会话断言 |
| 匿名 context 拿不到 `/backend/prototype` | 权限不是只在菜单里隐藏，路由本身也拦 |

一次登录供三条用例共用：登录接口限 5 次/分/IP，而 `--full` 里还有别的门也在登录。

**负向对照**：把某一页的 href 指向不存在的路由 → `应该 200` 断言失败、退出码 1；还原后 3/3 通过。这不是"跑绿了"，是"改坏了会红"。

**仍然不做**：不做像素比对（那是 `ui-regression` 的事）、不替代人工看视觉（配色/密度这类只能靠眼睛）。


## 边界状态覆盖（目标原文要求，第 61 轮补齐并纳入浏览器断言）

| 状态 | 页面 | 文案要点（为什么这样处理） |
|---|---|---|
| 空 | 开发任务 | 给"下一步做什么"，不是只写"暂无数据" |
| 错误 | 开发任务 | 复用列表页已修的错误分支 |
| 无权限 | 开发任务 | **返回 404 而不是 403**，避免泄露"存在" |
| 额度耗尽 | 开发任务 | 12/12，排队或主管提额 |
| 重复 | 开发任务 | 只说"已存在 + 归属人 + 最近更新"，**不展示对方客户资料** |
| 并发冲突 | 开发任务 | 版本 7 → 8，刷新重试，不覆盖对方修改 |
| 发送未知 | 邮件草稿审批 | **先查询、不重发**——重发会让同一收件人收到两封 |
| 已取消 | 开发任务 | Run cancelled：额度退回，不再有新候选 |
| 连接中断 | 开发任务 | 重连后从上次游标继续，不重复提交；10 分钟未恢复按已取消处理并退回额度 |

`crm-prototype.spec.ts` 逐条点击并断言上面那句关键文案——**标签存在而文案缺失等于没演示**，所以断言的是处理方式而不是状态名。


## 正式界面闭环（M7，2026-11-09）——原型不是交付

原型六页仍然是 `navHidden` 的演示页，**不进入任何业务菜单，也不算「收敛」**。正式闭环跑在核心模块的真实页面上：

- 入口：`/backend/customers/companies`（销售业务区「公司」）→ 公司详情 `/backend/customers/companies/<id>`。
- 记录跟进：详情页 Notes 区 → `POST /api/customers/comments`，**真实落库**（`customers.activities.manage`），employee 可写；验证后已删除测试记录。
- 生成草稿：详情页右上「写邮件」→「保存草稿」→ `POST /api/messages` + `isDraft:true` + `objects:[{entityModule:"customers",entityType:"company",entityId}]`，**草稿落库、不外发**（返回 `isDraft:true`、`sentAt:null`，drafts 文件夹 `status:"draft"`）；验证后已删除。
- 不引入 `leadgen_*` 迁移；原型页的数据仍是静态占位，两者不要混用同一口径。

同日的主侧栏收敛（22 个「创建 X」对象级菜单项下沉到列表页操作区，员工可见减少 10 条）见 `01-entry-map.md` §11。
