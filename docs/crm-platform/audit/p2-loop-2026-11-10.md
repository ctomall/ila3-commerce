## 更正：草稿在 UI 里是可见的，之前的“文件夹切换失效”是自动化点击没打中

第 69/74 轮记录“文件夹切换不生效、草稿看不到”，本轮复核后**撤回该结论**：

- 用 `button[aria-haspopup=menu]`（“文件夹:收件箱”）→ 菜单项 `role=menuitemradio` 上派发完整
  pointer/mouse 序列后，按钮标签变为“文件夹:草稿”，列表出现两条草稿（`p2-drafts-visible-2026-11-10.png`）；
- 点击行进入 `/backend/messages/097b867e…`，详情显示标题、正文、作者
  `acceptance-employee@example.test`、关联对象 `Copperleaf Design Co.`（`p2-draft-detail-2026-11-10.png`）。

之前的失败是脚本用 `.click()`/ref 点击时目标未命中（菜单在 portal 里、快照 ref 过期），不是产品缺陷。
教训：UI 交互失败要先区分“控件没响应”与“点击没到达”，否则会把自动化问题写成产品缺陷。

仍未中文化的只剩详情页少量文案：`← Back to messages`、`Conversation actions`、`Attached objects`、`active`。

## 中文补齐：消息撰写框不再回退英文（d1d3409，2026-11-10 07:37 已上线）

现象（修复前截图 `p2-compose-en-before-2026-11-10.png`）：撰写框里 `保存草稿/取消/发送` 已是中文，
但优先级仍是 `Low/Normal/High/Urgent`，附件按钮是 `Choose files`。

根因：`messages.priority.{low,normal,high,urgent}` 四个键不在词典；`attachments.library.upload.choose`
在词典里但它属于 `attachments` 命名空间，而 `auth-dict` 的 `customers` / `messages` 区域没有打包该命名空间，
于是回退英文。

修复：补四个优先级键（中/英），并把 `attachments` 加入两个区域命名空间；auth-dict 测试 15/15、typecheck 0。

验证（修复后截图 `p2-compose-zh-after-2026-11-10.png`，同一账号、同一 1280×900 视口）：
撰写框按钮为 `保存草稿 / 取消 / 发送 / 低 / 普通 / 高 / 紧急 / 选择文件`。
