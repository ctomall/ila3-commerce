# ILA3 Commerce 前端 UI 规划（使用为主）

> 审查方式：真实浏览器加载 + 计算样式测量（1440/1280/900/768 四档视口），
> 未修改任何代码。所有数值均为当场实测；未知项以方括号占位。

## 方向（五句话）

- **产品**：面向内部运营与销售的 B2B 履约后台（客户、商机、报价、订单、库存、收款）。
- **性格**：快、准、克制。使用者的目标是"把手上的单据处理完"，不是"欣赏界面"。
- **世界**：仓库、单据、标签、纸箱。中性灰底 + 单一强调色，彩色只出现在状态与数据本身。
- **时刻**：数据表（密度与对齐就是产品质感）、单据编号与金额（等宽数字）。
- **签名**：所有编号/金额用 `tabular-nums` 对齐；状态用一个小圆点 + 中文词，不用彩色胶囊。

## 1. 现状审查（按影响使用效率排序）

| # | 问题 | 实测证据 | 对使用的影响 |
|---|---|---|---|
| 1 | **侧边栏是 79px 图标栏，41 项、内容高 2013px** | 折叠宽 79px / 展开 239px；高度 2013px（展开 2505px）；单行 40px | 900px 高视口要滚动约 2.8 屏才能看到后半段菜单；图标栏下标签不可见，全靠记忆与悬停，**新人与跨模块操作最痛** |
| 2 | **列表行高 49px、6 列等宽** | `th` 37px、`td` 49px、表宽 1124–1284px | 一屏只看到约 3 行数据；B2B 巡检要连续扫几十行，密度不足直接拉长操作时间 |
| 3 | **搜索框高 20px** | `input` 计算高 20px（全站一致） | 点击/聚焦目标远低于 24px 可用下限，误触与多次尝试 |
| 4 | **页面标题弱、且与面包屑重复** | `h1` 16px/600 位于内容卡片内；面包屑同时显示「公司」 | 层级不清晰，扫视时找不到"当前在哪"的锚点 |
| 5 | **列表失败态曾被吞成空状态** | 已修复（客户/联系人）：现在 `role="alert"` + 插图 + 重试提示 | 剩余页面仍依赖包内实现，未逐一验证 |
| 6 | **焦点可见性不一致** | 链接 `outline: auto`（浏览器默认浅灰）；「切换侧边栏」按钮 `outline: none` + 阴影；搜索框程序化聚焦无环 | 键盘用户丢失位置，表单出错时更难定位 |
| 7 | **部分可访问名称仍是英文** | `Open AI assistant`、`Open global search`、`Notifications`、`organizationSwitcher` | 中文产品的读屏体验断层 |
| 8 | **裁剪路由的 Cookie 文案回退英文** | `/backend` HTML 含 `notices.cookies.description`（1 次）；`/backend/customers/companies` 含 **0 次**，页面显示英文 | 中文覆盖率回退，且只在部分路由出现，难被例行检查发现 |
| 9 | **工具条控件碎片化** | 「筛选」「视图」「全部视图」三个独立控件 + 搜索 + AI 按钮 | 完成一次"只看待跟进客户"要 2–3 次点击 |
| 10 | **工作台信息密度低** | 3 张等宽卡片；每行 ~90px；每条重复「查看记录」链接；空卡片占满一列 | 一屏仅 5 条记录；重复链接是纯粹的点击成本 |
| 11 | **装饰性噪声** | 搜索旁「AI」闪光按钮、页脚「用时 446ms」 | 暴露实现细节，干扰判断 |
| 12 | **圆角令牌冗余** | `--radius` `.625rem`、`--radius-lg` `.625rem`（相等）、`--radius-sm` `calc(.625rem - 4px)` | 不是使用问题，但会让后续视觉调整失效 |

**判定：轻 slop（polish 模式）。** 骨架、配色、组件体系是干净的，问题集中在密度、状态与控件组织。

## 2. 页面与组件目标

| 页面 | 主要用户任务 | 成功路径 | 信息架构位置 |
|---|---|---|---|
| `/backend` 工作台 | 判断"今天先做什么" | 3 秒内看到待办数量 → 一键进入对应列表 | 一级，登录后默认落点 |
| `/backend/customers/companies` | 找到某公司并打开 | 搜索/筛选 → 行内打开详情 | 客户关系 → 公司 |
| `/backend/customers/deals` | 推进商机阶段 | 按阶段筛选 → 改阶段 | 客户关系 → 商机 |
| `/backend/catalog/products` | 查价与库存 | 搜索 SKU → 看到价格/库存 | 商品目录 → 产品 |
| `/backend/sales/orders` | 处理订单状态 | 按状态筛选 → 打开单据 | 销售 → 订单 |
| `/backend/wms` 运营看板 | 发现异常 | 异常计数 → 进入明细 | 库存仓储 → 运营看板 |
| `/backend/config/*`（8 组） | 改配置 | 分组 → 页面 → 保存 | 设置（二级） |
| `DataTable`（组件） | 扫读、排序、批量操作 | 表头排序 + 行选择 + 行操作 | 所有列表页复用 |
| `ListEmptyState` / `SearchEmptyResults` / `EmptyState` | 解释"为什么没有数据" | 给出下一步动作 | 所有列表与搜索 |

## 3. 布局与视觉层级

**外壳**（实测结构，保持不改）

```
[侧边栏 79px 折叠 / 239px 展开]  [顶栏]  [内容区 1350px]
                                    ↑ 页头：面包屑 + 标题 + 主操作
                                    ↑ 工具条：搜索 + 筛选 + 视图
                                    ↑ 数据表 + 分页
```

**调整建议（按优先级）**

1. **侧边栏默认展开 240–280px**，折叠是用户主动选择并记住状态；分组折叠默认只展开当前分组，其余收起 → 41 项压到 1 屏内可扫。
2. **列表密度**：`td` 49 → **40px**（首列可 48px），`th` 37 → **36px**；行内边距 12px。目标：900px 视口一屏 **≥12 行**。
3. **标题层级**：页面标题 16 → **20px/600**，并移出内容卡片（与面包屑同一栏），卡片只承载工具条与数据。
4. **操作区**：主操作（新建/保存）放页头右上；次操作（导出、批量）放工具条；辅助（视图、列设置）收进「⋯」。
5. **工具条合并**：搜索 + 筛选 + 视图 收进一条 36px 高的行内；筛选项以 chip 形式回显，可单个移除。
6. **数字对齐**：金额、数量、编号统一 `tabular-nums` 右对齐。

## 4. 设计令牌复用

> 令牌名保持原样，不得重命名。

| 类别 | 复用令牌 | 用法约束 |
|---|---|---|
| 表面 | `--background`、`--card`、`--popover` | 页面底 `--background`，卡片 `--card`，浮层 `--popover` |
| 文本 | `--foreground`、`--muted-foreground` | 正文三级：主（`--foreground`）、次（`--muted-foreground`）、弱（同色 + `opacity`） |
| 描边 | `--border`、`--input`、`--ring` | 分隔线一律 `--border`；输入框 `--input`；焦点 `--ring` |
| 强调 | `--primary`、`--primary-foreground`、`--brand-violet`、`--brand-lime` | 主按钮用 `--primary`；`--brand-*` 仅用于品牌标记，不用于控件 |
| 状态 | `--destructive`、`--destructive-foreground` | 仅表示错误与危险操作 |
| 圆角 | `--radius`（10px）、`--radius-sm`（6px）、`--radius-lg`（10px） | 控件 8–10、卡片 12–16；**注**：`--radius` 与 `--radius-lg` 当前相等，建议保留 `--radius` 作卡片、`--radius-sm` 作控件 |
| 布局 | `--sidebar`、`--sidebar-foreground`、`--sidebar-border` | 侧栏专用，勿在内容区复用 |
| 间距 | `[spacing 令牌名]` | 当前未见间距令牌，按 4px 栅格直接取值；若后续引入，统一替换 |

**缺失占位**：`[字体族令牌]`、`[字号令牌]`、`[断点令牌]` 在 `globals.css` 中未找到对应的命名令牌，规划阶段以 `[占位]` 标注。

## 5. 状态设计

| 状态 | 视觉表现 | 文案要点 | 现状 |
|---|---|---|---|
| **empty** | `EmptyState` 插图（`/brand/state-empty.svg`）+ 标题 + 一句原因 + 一个主操作 | 说清"为什么空"与"下一步做什么"，不用「暂无数据」四个字打发 | ✅ 已有（3 个渲染器全覆盖） |
| **loading** | `SkeletonTable` 稳定列宽 + `aria-busy`；不做全屏 spinner | 首次加载 200ms 内不出骨架，避免闪烁 | ✅ 组件已交付，列表页接入待补 |
| **error** | `role="alert"` + `/brand/state-error.svg` + 中文标题 + 重试 + 原始错误（小字） | 标题说人话（「加载失败」），技术细节降级到第三行 | ✅ 客户/联系人已接入；其余页 `[待接入]` |
| **hover** | 行背景 `--muted`/8%；按钮仅变色；位移 ≤0 | 不放大、不发亮 | `[待确认]` 现有实现 |
| **focus** | 统一 `2px` `--ring` + `2px` offset，所有可交互元素一致 | 键盘可见，鼠标点击不显示 | ❌ 当前不一致（见 §1.6） |
| **disabled** | 文本 `--muted-foreground`、背景不变、`cursor: not-allowed`、`aria-disabled` | 说明为何不可用（tooltip） | `[待确认]` |

## 6. 响应式行为

实测：`≥1024` 显示侧栏；`≤900` 侧栏隐藏并出现「打开菜单」；表宽自适应，`768` 无横向溢出。

| 断点 | 布局变化 | 优先级调整 |
|---|---|---|
| `≥1280`（`xl`，实测） | 侧栏 239px + 内容 1350px，表格全列 | 全部列可见 |
| `1024–1279`（`lg`，由 `hidden lg:block` 推断） | 侧栏展开或折叠，表格按 `[列优先级]` 隐藏次要列 | 名称、状态、金额优先 |
| `768–1023`（`md`，`[断点值待确认]`） | 侧栏隐藏，抽屉式导航；工具条换行 | 主操作固定在页头 |
| `<768`（`sm`，`[断点值待确认]`） | 单列；表格转「两行式」行布局（主字段 + 次字段），不做横向滚动 | 只保留 3 个关键字段 |

> 断点来源：`--breakpoint-*` 令牌未在 `globals.css` 中确认，当前以 Tailwind 默认值与实测行为为准；落地前需以 `[断点令牌]` 复核。

## 不做什么

- 不改配色体系、不改组件名、不改路由；
- 不加渐变、光晕、玻璃拟态、装饰插图；
- 不为"好看"增加动效；动效只用于反馈（≤150ms）；
- 不重命名任何令牌与类名。

## P1 执行结果（2026-11-06，已上线并实测）

| 项 | 改造前 | 改造后 | 验证方式 |
|---|---|---|---|
| Cookie 文案（裁剪路由） | `/backend/customers/companies`：`notices.` = **0**，页面英文 | `notices.` = **20**，中文 | curl HTML key 计数 + 浏览器 DOM 三路由 |
| 可访问名称 | `Open AI assistant` / `Open global search` / `Notifications` / `organizationSwitcher` | 打开 AI 助手 / 打开全局搜索 / 通知 / 组织: Acme Corp | DOM `aria-label` 抓取 |
| 键盘焦点 | 链接 `outline: auto 1px`；按钮 `none`；搜索框无环 | 全部 `solid 2px` + `offset 2px` | `Tab` 5 次逐项读计算样式 |
| 页面体积 | companies 931 490 B / products 625 798 B | companies **970 092 B** / products **664 400 B**（+38.6 KB，+4.1%） | curl 实测 |
| `/login` | 108 KB / 823 键 | 108 KB / 823 键（未变） | curl 实测 |
| 44 页回归 | — | 44/44 中文、0 个 404、0 个报错 | 浏览器逐页扫描 |

**为什么体积 +38.6 KB**：外壳（通知铃、组织切换器）用到的命名空间必须随裁剪页保留。
`ai_assistant`(38 KB) 与 `search`(16 KB) 整包放行会带来 **+172 KB**，因此改用**按 key 白名单**
（只放行 `ai_assistant.launcher.*` 与 `search.dialog.actions.*`），代价降到 38.6 KB。
已实测 AI 面板与搜索弹窗打开后无裸 key 泄漏。

**两处残留判定为非缺陷**：`/backend/config/customers` 的 `in_progress` 是字典编辑页的「值」列；
`/backend/config/ai-assistant/agents` 的 `search.hybrid_search` 是工具标识符，同页已显示中文「混合搜索」。

## P0 执行结果（2026-11-06）

### 先更正审计里两处测量错误

| 原结论 | 实测复核 | 结论 |
|---|---|---|
| 「侧栏默认折叠 79px」 | 清掉 `om_sidebar_collapsed` cookie 后为 **239px 展开**；79px 是我自己在审计中点击折叠按钮留下的状态 | **不是缺陷**，侧栏默认宽 239px 已在 240±目标区间 |
| 「搜索框高 20px」 | 20px 是内层 `<input>`；外层可点击容器为 **36px** | **不是缺陷**，点击目标够大 |

真正的侧栏问题是：**18 个分组全部展开，导航内容高 2505px**（900px 视口约 2.8 屏）。

### 已落地：列表密度

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 行高 `td` | 49px | **41px** |
| 表头 `th` | 37px | **29px**（比计划的 36 更紧，属超预期方向） |
| 900×800 一屏可容纳行数 | 11 | **13**（目标 ≥12） |
| 补丁 | 20 | **21**（新增 `density-table-cells`） |

实现：`primitives/table.js` 的 `TableCell` / `TableHead` 由 `py-2` 改 `py-1`（受管补丁，构建期校验）。

### 未完成：侧栏分组默认折叠

尝试过的方案：在 `AppShell.js` 的 `openGroups` 初始化里只展开当前路由所属分组。

**失败原因（已定位）**：侧栏有两套 key —— 分组用 `resolveGroupKey(g)`，而实际渲染用的是
`settings:${section.id}`；只初始化前者时 `openGroups[key] !== false` 对所有 section 仍为真，
补丁**完全无效**。按纪律撤回了该补丁（不留惰性补丁），补丁数 22 → 21。

下一轮的正确做法：改 `open` 的**判定式**（第 642 / 840 行两处），而不是初始化数据，
并对 `settings:` 前缀的 key 一并生效；验收仍是「导航 900px 视口一屏可达」。
